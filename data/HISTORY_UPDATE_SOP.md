# 历史数据更新与联赛覆盖 SOP

> 创建：2026-09-06。解决"历史数据断层、竞彩受注联赛与历史库不对等、如何更新"的标准操作。

## 一、数据现状（2026-09-06 核查）

- 历史库：36 联赛、约 10.1 万场，最早 2012-03。
- 断层结构：
  - **跨年度欧洲联赛（26个）**：数据止于 2026 年 5 月（2526 赛季完赛），缺 2627 新赛季开局 2-3 轮（8 月中下旬开赛）。
  - **自然年联赛（10个：ARG/BRA/CHN/FIN/IRL/JPN/MEX/NOR/SWE/USA）**：多数到 2026-08 初，仅缺约 1 个月；**JPN 异常只到 2025-12-06，缺口最大，优先补**。
- 数据源：football-data.co.uk，CSV，含欧赔/亚盘/大小球/射门；**2627 赛季起新增原生 HxG/AxG（真实 xG），proxy_xg 可对覆盖联赛升级为真实 xG**。

## 二、更新通道（关键坑，已踩平）

1. **数据中心 IP 直连 football-data 被封**：curl / requests / urllib 全部 HTTP 503（首页都 503），重试、换 UA 均无效。GitHub 镜像要么停更（footballcsv 停在 2020-21）、要么只有五大联赛且为精简格式（datasets/football-datasets），都不可用。
2. **唯一稳定通道 = LLM 的 web.fetch 工具**（走平台代理）。已验证可下 E0/SP1/F1 等完整 CSV。
3. **间歇性 link fetch error 是抖动**：同一 URL 重试即可；某联赛 2627 文件可能尚未发布（如 I1 2627 暂缺但 2526 正常），等几天再下，不影响其他联赛。
4. **URL 代码 ≠ 本地 Div 命名**：荷甲 URL 是 `N.csv`、文件内 Div=N1、本地文件 N1_history.json。全部映射以 `data/league_source_map.json` 为准。
5. **赛季代码**：跨年度联赛当前=2627；自然年联赛当前=2526（与欧洲 2025-26 时间窗重叠），次年 3 月前后切 2627。

## 三、标准更新流程（每期/每轮按需执行）

```bash
cd jingcai-football-plugin/data
# 1. 生成全部联赛当前应下载的URL清单
python3 merge_csv_update.py --urls
# 2. LLM用web.fetch逐个获取URL完整CSV（snippet模式, max_length≥12000, mode=full），
#    Write保存到 data/downloads/<Div>_<season>.csv（如 SP1_2627.csv）
# 3. 批量转换+增量合并去重（字段严格对齐history JSON，自动识别HxG/AxG）
python3 merge_csv_update.py --dir downloads/
# 4. 查看更新后各联赛时间范围/射门/xG覆盖
python3 merge_csv_update.py --status
# 5. 重训ML模型（不要加--evaluate，5折CV在10万样本上会超时；CV结论稳定无需每次跑）
python3 train_ml_model.py
```
- 合并按 (date,home,away) 去重，已存在则补全字段、不存在则新增，自动按日期排序。
- 单文件：`python3 merge_csv_update.py --csv downloads/E0_2627.csv --league E0 --season 2627`。
- 旧的 `update_history.py` 字段名与现库不一致（half_time_home vs hthg）且走被封的 urllib，**已废弃，不要再用**。

## 四、竞彩受注联赛覆盖（2026-09-06 在售 46 场实测）

- 历史库覆盖 43/46 场 = **91.5%（按场次）**，12/14 联赛 = 85.7%。
- 仅缺：**沙特职业联赛(SAU)、韩国K联赛(KOR)**；杯赛（欧冠/亚冠/解放者杯等）不做常驻库、受注时按需补。
- 免费补全源：**FBRef 同时覆盖沙特联(2026-27在更)与韩K联(comps/55，2026在更)、日本J1，含 xG/射门，免费**。补全时写一个 fbref_csv→history JSON 的适配器（字段映射到同一 schema），作为 merge_csv_update 的第二个 source。

## 五、联赛不对等，ML 为什么依然成立（已用数据验证）

- 模型 15 特征中，**赔率隐含概率合计占特征重要性 82.9%**（imp_away 42.6%+imp_home 31.1%+imp_draw 9.2%），这些特征只要有竞彩赔率/欧指就可得，**不依赖历史库**；其余 17.1% 是近期状态/射门等增量特征。
- 留出实测（2026-09-06）：有射门历史的 23 联赛准确率 53.5%，**无射门历史、增量特征被填充的 13 联赛仍有 52.5%**，仅低 1pct，均远超 33% 随机基线。
- 结论：模型学的是"攻防/赔率→赛果"的通用关系，**可跨联赛迁移**。对无历史库联赛（沙职/韩职/小联赛/杯赛）：
  1. 模型照跑，以市场赔率特征为主、模型为辅；
  2. 缺失的增量特征用**联赛均值 + 贝叶斯收缩**向全局均值回归，不报错、不跳过；
  3. 小联赛市场定价效率低、赔率噪声大，应**降低该类联赛的 Kelly 仓位、提高 EV 门槛**，而不是不分析。
- 因此正确策略不是"凑齐所有联赛才训练"，而是"覆盖竞彩高频联赛保证增量增益 + 通用模型兜底长尾联赛 + 仓位按数据完整度分层"。

## 六、更新频率建议

- 跨年度联赛：每周一轮，周末赛完后下一次赛前分析前批量补一次即可；赛季初（8月/1月）新文件发布密集，多查一次。
- 自然年联赛：同理按轮次补；JPN 立即补历史欠账。
- 模型不必每次更新都重训：累计新增较多（≥一轮，约几百场）或每月重训一次即可；单次几场对 10 万样本模型无影响（本次 +17 有效样本，准确率 52.9%→53.0%）。
